# TASK-504. Админка менеджера mobile-first

## Контекст

Заказчик работает с админкой (`admin/`, Next.js, :3002, `admin.paradise.kz`)
в основном с телефона — и заказы, и товары, и склад, и документы. Админка
свёрстана под десктоп: во всём `admin/src` 39 адаптивных классов.

Что ломается на экране 375 px:

- **Каркас.** `ProtectedRoute` рисует `Sidebar` фиксированной ширины `w-64`
  рядом с `<main className="flex-1 overflow-y-auto p-8">`. Сайдбар занимает
  256 из 375 px, мобильного меню нет.
- **Двойные отступы.** Семь страниц (`/`, `orders`, `orders/[id]`, `products`,
  `products/[id]`, `stock`, `users`) заворачивают себя в
  `min-h-screen … p-6` поверх `p-8` у `<main>`: 56 px с каждой стороны.
- **Таблицы.** `ui/DataTable` используется в 21 месте (17 страниц и 4 вкладки
  товара). Обёртка — `overflow-hidden` без горизонтальной прокрутки: колонки
  сжимаются или обрезаются. Ещё три таблицы свёрстаны руками —
  `products/page.tsx`, `stock/page.tsx`, `users/page.tsx`.
- **Только по наведению.** В списке товаров «Редактировать» / «Удалить» —
  `opacity-0 group-hover:opacity-100`: на сенсорном экране их не видно.
- **Меню действий заказа.** `OrderRowActions` — выпадашка `position: fixed` от
  координат кнопки «⋯»; на телефоне это мелкие пункты у края экрана.
- **Модалки** — по центру, `max-w-lg`, кнопки внизу длинной формы уходят
  под клавиатуру.
- **Вкладки** (`ui/Tabs`, `orders/OrderTabs`) переносятся в несколько рядов.
- **Поля ввода** — `text-sm` (14 px): iOS Safari зумит страницу при фокусе.
- **Тосты** — `fixed bottom-4 right-4 w-80`.
- **Формы** — `grid-cols-2` без мобильного варианта (`GoodsReceiptForm`,
  `BannerForm`, `CollectionForm`, `VariantsTab`, формы складов и поставщиков).

## Цели

1. Каждый экран `admin/` пригоден для ежедневной работы на телефоне от 360 px:
   читается без горизонтальной прокрутки, все действия доступны пальцем.
2. Навигация на телефоне — нижняя панель, как в мобильном приложении.
3. Десктоп (≥ 1024 px) выглядит и работает как сейчас.
4. С карточки заказа можно позвонить клиенту и написать ему в WhatsApp.

## Не цели

- **Filament** (`/admin` на API-хосте). Задача — только папка `admin/`.
- Бэкенд: API не меняется, PHP-тестов нет.
- Счётчик новых заказов на нижней панели, PWA / установка на главный экран,
  push-уведомления. Отдельные задачи, если понадобятся.
- Редизайн десктопа, новая цветовая схема, тёмная тема.
- Новые npm-зависимости (иконки — инлайн SVG, как уже принято в коде).

## Решения

### Mobile-first и точки перелома

Базовые классы Tailwind пишутся под телефон. Две точки перелома:

| Ширина | Навигация | Списки |
|---|---|---|
| < 768 px (`md`) | нижняя панель | карточки |
| 768–1023 px | нижняя панель | таблица |
| ≥ 1024 px (`lg`) | сайдбар | таблица |

Порог «карточки / таблица» (`md`) живёт в одной константе
`admin/src/lib/breakpoints.ts` и используется и в хуке `useIsDesktop()`,
и в комментариях к классам, чтобы CSS и JS не разошлись.

Правила для всех экранов:

- Интерактивный элемент на телефоне не меньше 44×44 px.
- Поля ввода `text-base md:text-sm` — 16 px на телефоне против зума iOS.
- Ничего не показывается только по `hover`.
- Безопасные зоны: `export const viewport = { viewportFit: 'cover', … }` в
  `app/layout.tsx`, нижняя панель и закреплённые футеры учитывают
  `env(safe-area-inset-bottom)`.
- `window.confirm` остаётся: на телефонах это нативный диалог.

### Каркас

`ProtectedRoute` перестаёт рисовать разметку и отдаёт её новому
`components/shell/AppShell.tsx`.

- **< 1024 px.** Прокручивается документ, а не внутренний `overflow-y-auto` —
  так на iOS сворачивается адресная строка. Внизу `fixed` —
  `shell/BottomNav.tsx`: Заказы · Товары · Склад · Клиенты · Ещё.
  `<main>` получает нижний отступ под высоту панели плюс safe area.
- **≥ 1024 px.** Как сейчас: `Sidebar` слева, `h-screen`, прокрутка в `<main>`.
  `BottomNav` не рендерится (`lg:hidden`).
- **«Ещё»** открывает `shell/MoreSheet.tsx` — полноэкранное меню со всеми
  группами сайдбара и кнопкой «Выйти». Закрывается крестиком, Escape и
  переходом по ссылке. «Ещё» подсвечено, когда текущий раздел не входит в
  четыре главных.
- **Один конфиг меню.** Группы и ссылки переезжают из `Sidebar.tsx` в
  `shell/navConfig.ts`; его читают `Sidebar`, `BottomNav`, `MoreSheet`.
  Там же — `isActive(pathname, href)` и список четырёх главных разделов с
  иконками. Названия групп по-прежнему отличаются от названий ссылок
  (e2e и скринридеры не должны видеть два элемента «Склад»).
- **Отступы** задаёт `AppShell`: `px-4 py-4 md:px-6 lg:p-8`, контент
  `mx-auto max-w-7xl`. Обёртки `min-h-screen … p-6` и `max-w-7xl mx-auto`
  со страниц удаляются; более узкие (`max-w-4xl` у товара, `max-w-6xl` у
  заказа) остаются как внутренние.
- **Тосты** на телефоне — во всю ширину (`inset-x-4`) над нижней панелью;
  с `md` — как сейчас, справа внизу.
- **Главная** (`/`) остаётся как есть и доступна через «Ещё».

### DataTable: карточки на телефоне

Контракт `Column<T>` расширяется необязательным полем:

```ts
type MobileRole = 'title' | 'badge' | 'meta' | 'actions' | 'hidden';

type Column<T> = {
  key: string;
  header: string;
  render: (row: T) => ReactNode;
  className?: string;
  mobile?: MobileRole;
};
```

Раскладка карточки по ролям:

```
┌──────────────────────────────────┐
│ title                     badge  │
│ meta · meta · meta               │
│ Заголовок колонки   значение     │  ← колонки без роли
│ actions                          │
└──────────────────────────────────┘
```

- Колонка без `mobile` выводится строкой «`header`: значение». Поэтому уже
  после этапа 1 все 21 место с `DataTable` читаются на телефоне без правок.
- `className` колонки в карточке не применяется: табличные классы
  (`text-right`, `whitespace-nowrap`) карточке не нужны.
- Новые необязательные пропсы `DataTable`:
  - `card?: (row: T) => ReactNode` — своя разметка карточки целиком, для
    ключевых экранов;
  - `rowHref?: (row: T) => string` — вся карточка кликабельна. Карточка не
    оборачивается в `<a>`: внутри неё живут кнопки действий и `tel:`, а
    интерактивный элемент внутри ссылки — невалидный HTML. Вместо этого
    «растянутая ссылка»: `<Link>` с `absolute inset-0` поверх карточки, а
    блок `actions` и ссылки внутри ячеек — `relative z-10`, выше неё.
    Доступное имя ссылки — содержимое колонки `title`.
- **В DOM только один вариант.** `DataTable` выбирает карточки или таблицу
  хуком `useIsDesktop()` (`matchMedia` + `useSyncExternalStore`), а не
  прячет один из вариантов CSS. Иначе удваиваются меню действий, а e2e
  `getByText` находит скрытую копию и падает в strict mode. Серверный снимок
  хука — `false`: все экраны админки рендерятся на клиенте после
  `ProtectedRoute`, так что расхождения гидрации нет.
- Таблица получает обёртку `overflow-x-auto` (сейчас `overflow-hidden` режет
  широкие таблицы и на десктопе).
- Пагинация на телефоне — «Назад» / «Вперёд» на всю ширину, «Стр. N из M»
  над ними.
- Состояния «Загрузка…» / пусто — одна карточка с тем же текстом.

### Модалки и меню действий

- **`ui/Modal`** на телефоне — шторка снизу: во всю ширину, `rounded-t-2xl`,
  высота до `90dvh`, прокрутка внутри. С `md` — по центру, как сейчас.
  Escape и клик по фону закрывают, как сейчас.
- **`ui/CrudModal`**: футер с «Отмена» / «Сохранить» закреплён внизу шторки
  (`sticky bottom-0`), кнопки на телефоне во всю ширину.
- **`ui/ActionSheet` (новый)** — список действий, выезжающий снизу, с
  отдельной кнопкой «Закрыть». Деструктивные пункты — красным.
  `OrderRowActions` на телефоне открывает его вместо выпадашки; на десктопе
  выпадашка остаётся.

### Остальные общие компоненты

- **`ui/PageHeader`**: на телефоне `sticky top-0` с фоном страницы и
  `backdrop-blur`; стрелка «назад» 44×44; заголовок `text-xl md:text-2xl`;
  `actions` переносятся под заголовок (`flex-wrap`), а не за край экрана.
- **`ui/Tabs`, `orders/OrderTabs`**: одна строка с горизонтальной прокруткой
  (`overflow-x-auto`, `whitespace-nowrap`, скрытая полоса прокрутки).
  Счётчики на вкладках статусов сохраняются.
- **`ui/styles.ts`**: `inputClass` — `text-base md:text-sm`; кнопки —
  `min-h-11 md:min-h-0`.
- **Формы**: `grid-cols-2` → `grid-cols-1 sm:grid-cols-2`.
- **Фильтры списков**: на телефоне столбиком, поиск во всю ширину.
  `stock-movements` (шесть фильтров) на телефоне сворачивает их под кнопку
  «Фильтры (N)», где N — число активных.
- **`ui/EntityPicker`** на телефоне открывается на весь экран: поле поиска
  сверху, результаты крупными строками.

### Звонок и WhatsApp из заказа

Телефон клиента в заказе — только `order.user.phone` (у гостей тоже:
гостевой заказ создаёт пользователя с `is_guest`). Формат не гарантирован,
поэтому `admin/src/lib/phone.ts` повторяет правила `App\Support\Phone`:
только цифры; 11 цифр на `8` → `+7…`; 10 цифр → `+7…`; иначе `+` и цифры.

- `tel:+77071234567` — «Позвонить».
- `https://wa.me/77071234567` — «WhatsApp», открывается в новой вкладке
  (`rel="noopener"`).
- Кнопки показываются, только если после нормализации получилось `+` и
  от 11 до 15 цифр (длина E.164; казахстанский номер — 11). Пустой номер,
  строка без цифр или слишком короткий номер — кнопок нет, телефон
  выводится текстом как есть.

Кнопки — в блоке «Клиент» карточки заказа и в карточке заказа в списке
(телефон кликабельный, отдельных кнопок в списке нет — только `tel:`).

## Этапы

Каждый этап — отдельный PR в `main` и отдельный деплой.

### Этап 1. Каркас и общие компоненты

- `AppShell`, `BottomNav`, `MoreSheet`, `navConfig`; `ProtectedRoute` и
  `Sidebar` на них.
- `viewport` в `layout.tsx`, тосты.
- `DataTable` с ролями, `card`, `rowHref`, `useIsDesktop`, `breakpoints.ts`.
- `Modal`, `CrudModal`, `ActionSheet`, `PageHeader`, `Tabs`, `OrderTabs`,
  `styles.ts`, формы в одну колонку.
- Удаление двойных отступов на семи страницах.
- Экран входа — проверить на 375 px (он уже почти адаптивный).

Результат: вся админка открывается и читается на телефоне; карточки пока
запасные «Заголовок: значение».

### Этап 2. Заказы и клиенты

- Список заказов — своя карточка: `#id` и номер, метка статуса, клиент и
  телефон (`tel:`), сегмент, сумма, дата; тап — в заказ; «⋯» — `ActionSheet`
  со сменой статуса.
- Карточка заказа: одна колонка на телефоне, статус и кнопка следующего шага
  сверху, степпер из четырёх шагов с подписями `text-xs`, «Позвонить» и
  «WhatsApp» в блоке «Клиент».
- `users/page.tsx` переезжает на `DataTable`; карточка клиента с крупной
  кнопкой «Одобрить».

### Этап 3. Товары

- `products/page.tsx` переезжает на `DataTable`; карточка: миниатюра,
  название, код, розничная и B2B-цена, статус, метки проблем; «Изменить» и
  «Удалить» видны всегда.
- `products/[id]`: закреплённая внизу панель «Отмена» / «Сохранить» на
  телефоне; вкладки связей прокручиваются; вкладки цен, характеристик,
  вариантов, цен клиентов — карточками через роли колонок.
- Фото: `<input type="file">` на телефоне сам предлагает галерею и камеру;
  лимит 10 МБ (`MediaTab.MAX_BYTES`) покрывает снимки с телефона.
- Английские подписи экрана (`Add New Product`, `Edit Product`,
  `Basic Information`, `Save Product`, `Cancel`, …) — на русский: эти строки
  всё равно переписываются.

### Этап 4. Склад, документы, справочники

- `stock/page.tsx` переезжает на `DataTable`.
- `stock-movements`: сворачиваемые фильтры, роли колонок.
- Приёмки и списания: списки, шапка документа, строки документа карточками,
  `EntityPicker` во весь экран.
- Склады, поставщики.
- Справочники и контент (категории, бренды, атрибуты, типы цен, группы
  каталога, подборки, баннеры, B2B-главная): роли колонок вместо запасных
  карточек.

## Тестирование

### Playwright

- В `admin/playwright.config.ts` — проект `Mobile` на `devices['Pixel 7']`
  (Chromium, WebKit ставить не нужно). Мобильные спеки лежат в
  `admin/e2e/mobile/`: `Desktop` их игнорирует, `Mobile` запускает только их.
  Оба зависят от `setup`.
- Существующие десктопные спеки не меняются и должны остаться зелёными —
  это проверка, что десктоп не сломан.
- **Нет горизонтальной прокрутки**: один тест обходит все маршруты
  навигации и по одному документу каждого вида (заказ, товар, приёмка,
  списание, группа каталога, подборка) и проверяет
  `document.documentElement.scrollWidth <= window.innerWidth`. Ловит
  главную мобильную поломку и на будущих экранах.
- Сценарии по этапам:

| Этап | Мобильные сценарии |
|---|---|
| 1 | нижняя панель переключает разделы и подсвечивает активный; «Ещё» показывает все группы и «Выйти»; форма в шторке (бренд) сохраняется |
| 2 | смена статуса заказа через `ActionSheet`; в заказе есть `tel:` и `wa.me` с нормализованным номером; одобрение B2B-клиента |
| 3 | редактирование товара и сохранение через закреплённую панель |
| 4 | создание приёмки со строкой товара через `EntityPicker` |

- `lib/phone.ts` — юнит-тест без браузера: `admin/e2e/unit/phone.spec.ts`
  импортирует функцию и проверяет её через `expect` Playwright, без фикстуры
  `page`. Отдельный проект `unit` (`testMatch: /unit\/.*\.spec\.ts/`, без
  зависимости от `setup`) — ни браузера, ни API ему не нужно, и новых
  npm-зависимостей не появляется. Случаи: `8 707 123 45 67`,
  `+7 (707) 123-45-67`, `7071234567`, `77071234567`, пустая строка,
  строка без цифр, короткий номер `12345` (кнопок нет). `Desktop` и `Mobile` игнорируют `e2e/unit/`.

### Проверки на каждый PR

`npx tsc --noEmit`, `npm run lint`, `npm run build` в `admin/` — как в CI.

### Визуальная проверка

Скриншоты ключевых экранов на 375 и 1280 px в панели браузера до и после
этапа. Вход в админку делает человек; сессия живёт в `localStorage`
(`admin_token`).

## Риски

- **Первый кадр `useIsDesktop()`** — `false`, то есть мобильная раскладка.
  На десктопе возможен один кадр карточек до таблицы; на практике экраны
  в этот момент показывают «Загрузка…», пока идут данные.
- **Классы ячеек в карточках.** Роль колонки задаётся на экране, и
  ошибиться с ней легко. Каждый переведённый экран проверяется глазами на
  375 px.
- **HEIC с iPhone.** `MediaTab` принимает `image/jpeg, image/png,
  image/webp`. Ожидается, что iOS сам отдаёт JPEG, когда HEIC не в `accept`;
  проверяется на реальном iPhone на этапе 3, эмулятор этого не покажет.
- **Высота шторки и клавиатура.** `90dvh` учитывает панели браузера, но не
  экранную клавиатуру; закреплённый футер `CrudModal` должен оставаться
  видимым при фокусе на последнем поле — проверить на телефоне на этапе 1.
