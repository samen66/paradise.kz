# Атрибуты на двух языках, характеристики в форме товара, фото вариантов

## Контекст

Менеджер (`admin/`, в основном с телефона — `2026-09-21-admin-mobile-first-design.md`)
попросил:

1. Атрибут с названием на двух языках: «Размер» на русском и казахском.
2. Переделать экран атрибутов по образцу крупных магазинов; в форме товара
   сразу создавать атрибут, категорию и бренд.
3. Прикреплять фото к варианту.
4. Цены для B2B-клиентов: при создании не виден список клиентов.

Состояние кода на 2026-09-25:

- `attributes.name` и `attribute_values.value` — простые строки. Бренды и
  категории уже переводятся (`HasTranslations`, JSON `{ru, kk}`).
- Характеристики товара — Collapsible-блок `AttributeValuesTab` с модалками,
  недоступен до первого сохранения товара.
- Характеристики варианта — свободный текст «Цвет: Серый» в textarea
  (`product_variants.characteristics` JSON), не связан с атрибутами. Фото у
  варианта нет. Вариантов в базе 0.
- Выбор клиента (`EntityPicker`) ничего не показывает, пока не набрано два
  символа; B2B-клиентов в базе двое — пустое поле выглядит сломанным. Сам
  `/admin/users` работает.
- Витрина фильтрует по строке `attribute_values.value`
  (`?filter[attr][color]=Серый`), фасеты отдают `values: list<string>`.

## Решения

| Вопрос | Решение |
|---|---|
| Что переводить | Название атрибута **и** значение; kk необязателен, при пустом показывается ru |
| Хранение переводов | JSON `{ru, kk}` через `HasTranslations`, как у брендов и категорий |
| Ключ фильтра витрины | ru-значение: URL одинаковый на обоих языках |
| Фото варианта | Отметка на фото товара; отметить из галереи или загрузить в варианте (фото попадает в галерею и сразу отмечено) |
| Характеристики варианта | Те же атрибуты, что у товара, с переводами |
| Характеристики товара | Часть основной формы, работают у нового товара, сохраняются общей кнопкой |
| Варианты и цены клиентов | Остаются отдельными блоками после первого сохранения, сохраняются сразу |

Вне этой работы: перевод экранов «Бренды» и «Категории» в новый вид;
справочник значений атрибута (список «Серый/Сұр» на выбор) — пока значения
вводятся текстом.

## 1. Данные и API

### Миграции

- `attributes.name`: string → JSON. Текущее значение переносится в
  `{"ru": <строка>}`. `Attribute` получает `HasTranslations`,
  `$translatable = ['name']`.
- `attribute_values.value`: string → JSON, тот же перенос. `AttributeValue`
  получает `HasTranslations`, `$translatable = ['value']`. Уникальный индекс
  `(product_id, attribute_id)` остаётся.
- Новая `product_variant_attribute_values`: `id`, `product_variant_id`
  (FK, cascade), `attribute_id` (FK, cascade), `value` JSON, timestamps,
  unique `(product_variant_id, attribute_id)`. Модель
  `ProductVariantAttributeValue` с `HasTranslations`.
- Новая `product_variant_media`: `product_variant_id` (FK, cascade),
  `media_id` (FK на `media.id`, cascade), `sort_order` unsigned int,
  primary `(product_variant_id, media_id)`.
- `product_variants.characteristics` не трогается — исторические данные ERP.
- `down()` возвращает строки из `ru`.

Миграции проверяются и на MySQL, и на SQLite (тесты) — изменение типа
колонки с переносом данных делается через временную колонку.

### Админский API

- **Slug необязателен** при создании атрибута, бренда, категории
  (`AttributeRequest`, `BrandController@store`, `CategoryController@store`).
  Без slug сервер берёт `Str::slug(name.ru)`; занятый — добавляет `-2`, `-3`…
  Логика в одном месте (трейт или небольшой класс в `app/Support`), покрыта
  тестом. Переданный slug по-прежнему проверяется на формат и уникальность.
- `AttributeRequest`: `name` — массив, `name.ru` required, `name.kk` nullable,
  оба ≤ 255.
- `GET /admin/attributes` отдаёт `values_count` (товары) и
  `variant_values_count` (варианты) через `withCount`.
- `DELETE /admin/attributes/{id}` — отказ 422, если есть значения у товаров
  **или** вариантов.
- `ProductSaveRequest` (store и update товара) принимает
  `attributes: [{attribute_id, value: {ru, kk}}]`:
  - `attributes` — необязателен; если ключа нет, характеристики не меняются;
    пустой массив — удалить все;
  - `attribute_id` — exists, без повторов в массиве;
  - `value.ru` required ≤ 255, `value.kk` nullable ≤ 255.
  Сохранение синхронизирует набор (создать / обновить / удалить отсутствующие)
  в одной транзакции с товаром. Ответ товара включает `attributes` в том же
  формате (с `attribute: {id, name, slug}`).
- Маршрут `products.attribute-values` и `AttributeValueController`
  удаляются вместе с `AttributeValueTab`: форма им больше не пользуется.
- `ProductVariantRequest` принимает `attributes` (тот же формат, та же
  синхронизация) и `media_ids: int[]` — только id из коллекции `images` этого
  товара, иначе 422. Порядок в массиве = `sort_order`. Ответ варианта
  включает `attributes` и `media: [{id, thumb, medium}]`.
- Загрузка фото из варианта — существующий `POST products/{id}/media`;
  возвращённый id фронт добавляет в `media_ids`.
- `UserController@index`: `allowedSorts('company_name', 'name')`; без `sort`
  порядок прежний (`latest()`), экран «Клиенты» не меняется.

### Публичный API (витрина, B2B-портал)

- `ProductResource::characteristicsPayload()`: `name` и `value` на языке
  запроса (`SetApiLocale`), при пустом kk — ru (fallback `HasTranslations`).
- `variantsPayload()`: `characteristics` строится из
  `product_variant_attribute_values` как `[{name, slug, value}]`; если у
  варианта их нет — из старого JSON в прежнем виде (объект), фронты
  поддерживают оба. Добавляется `images` в формате фото товара
  (`{thumb, medium, full}`), по `sort_order`. Контроллеры догружают
  `variants.attributeValues.attribute` и `variants.media`, без N+1.
- `FacetController::attributeFacets()`: `values: [{value, label}]`, где
  `value` — ru-значение (ключ URL), `label` — на языке запроса с откатом на
  ru. Сортировка по `label`. Название атрибута — на языке запроса.
- `ProductController::attributeFilter()` сравнивает
  `json_extract(attribute_values.value, '$.ru')` (как в `nameSort`, работает
  на MySQL и SQLite).
- Storefront `FilterSidebar` / `lib/types.ts` переходят на
  `{value, label}`: в URL `value`, на экране `label`.

## 2. Форма товара

### Карточка «Характеристики»

Collapsible-блок «Характеристики» уходит из `RELATIONS`. Вместо него —
карточка `AttributesSection` в левой колонке сразу после цен, в основной
форме react-hook-form.

- Строка: `[атрибут ▾] [значение] [✕]`. Над карточкой `LocaleSwitch` RU/KZ —
  переключает видимый язык значений; жёлтая точка — у какой-то строки пуст kk,
  красная — ошибка.
- «+ Добавить характеристику» добавляет строку и ставит фокус в выбор
  атрибута. Уже выбранные атрибуты в списке не предлагаются.
- Поле формы `attributes` через `useFieldArray`: грязность, сброс, SaveBar —
  как у остальных полей. Ошибки сервера `attributes.N.value.ru` ложатся на
  свою строку.
- Работает у нового товара: уходит в `POST /admin/products` вместе с
  остальными полями.
- Телефон: атрибут на всю ширину, под ним значение и ✕; цели касания ≥ 44 px.

Строки — общий компонент `AttributeRows` (используется и в варианте, §3).

### «+ Создать» в выпадающих списках

`SearchSelect` получает необязательный `onCreate?: (query: string) => void`.
Если введённого текста нет среди пунктов, последним пунктом идёт
«+ Создать „<текст>“». Без `onCreate` компонент ведёт себя как сейчас.

Пункт открывает шторку (`Modal`, снизу на телефоне):

| Шторка | Поля |
|---|---|
| `AttributeFormSheet` | Название RU * (из поиска), Название KZ, «Показывать в фильтрах витрины» |
| `BrandFormSheet` | Название RU * (из поиска), Название KZ |
| `CategoryFormSheet` | Название RU * (из поиска), Название KZ, Родительская категория (`SearchSelect` без «+ Создать») |

Slug не спрашивается — генерирует сервер. После успеха запись добавляется в
список и выбирается в поле; товар не сохраняется. Ошибка сервера — в шторке,
введённое в форме товара не теряется.

Списки категорий, брендов и атрибутов в `ProductForm` становятся состоянием
(с функцией добавления), чтобы созданное сразу было в списках.

## 3. Варианты с фото

Блок «Варианты» остаётся Collapsible «Сохраняется сразу», доступен после
первого сохранения товара.

**Список.** Строка: миниатюра первого фото (или заглушка), название,
характеристики одной строкой («Серый · 200×90»), розница, опт, остаток. На
телефоне — карточки (`DataTableCards`).

**Окно варианта** (шторка на телефоне, модалка на десктопе):

1. Название *, код, розничная и оптовая цены.
2. Характеристики — `AttributeRows` с RU/KZ и «+ Создать».
3. Фото — сетка фото товара с галочками; порядок отметки = порядок фото
   варианта. Последняя плитка «+ Загрузить»: файл проходит проверки
   `photos.ts` (JPEG/PNG/WebP, ≤ 10 МБ), уходит в `POST products/{id}/media`,
   попадает в галерею товара и сразу отмечается. Во время загрузки на плитке
   прогресс, «Сохранить» ждёт окончания. Галерея товара в форме обновляется.
4. «Ещё»: штрихкоды, по одному на строку.

Удалённое из галереи фото пропадает у вариантов (каскад).

**Витрина и B2B-портал.** `ProductInfo` в обоих уже переключает варианты.
Добавляется: у выбранного варианта есть `images` — галерея показывает их,
нет — фото товара. Характеристики варианта показываются переведёнными.

## 4. Экран «Атрибуты» (`/attributes`)

По образцу экранов склада (`/warehouse/stock`, `/warehouse/documents`).

- Поиск по названию (ru, kk) и slug. Чипы: «Все», «В фильтрах витрины»,
  «Без перевода», «Не используются». Поиск и чип — в URL. Фильтрация на
  клиенте (атрибутов десятки).
- Строка / карточка: название RU, под ним KZ или жёлтая пометка «нет перевода
  на казахский»; slug мелко; «в N товарах · M вариантах»; переключатель
  «В фильтрах» в строке — сохраняется сразу, тост об успехе или ошибке с
  возвратом переключателя.
- Действия «⋯» (`ActionSheet` на телефоне): «Изменить», «Удалить». Удаление
  используемого атрибута неактивно с пояснением «используется в N товарах».
- Пустое состояние (`EmptyState`): «Атрибутов пока нет — создайте первый или
  добавьте прямо в карточке товара».
- Создание и изменение — `AttributeFormSheet` из §2. Slug под
  «Дополнительно»: при создании пустой, при изменении редактируемый с
  предупреждением «изменит ссылки фильтров на витрине».

## 5. Выбор B2B-клиента

`EntityPicker`:

- При фокусе сразу открывает список: запрос без `filter[search]`, первые 20.
  Для клиентов — `sort=company_name` (новый необязательный проп `sort`).
- Ввод фильтрует через `filter[search]` с задержкой 300 мс, как сейчас.
- Клавиатура ↑ ↓ Enter Esc, `role="combobox"`, как в `SearchSelect`.
- Состояния: «Загрузка…», «Ничего не найдено», «Все клиенты уже с ценой»
  (когда всё исключено через `excludeIds`).
- Необязательный проп `description(item)` — вторая строка пункта. Для
  клиентов: компания; под ней имя и телефон; метка «не одобрен» для
  `is_approved = false` (цену задать можно, клиент увидит её после одобрения).

Остальные места с `EntityPicker` получают то же поведение без изменения их
кода.

## Ошибки

- Ошибки валидации — у своего поля или строки (`attributes.N.value.ru`,
  `media_ids.N`).
- Занятое название / slug при «+ Создать» — сообщение в шторке.
- Фото чужого товара в `media_ids` — 422.
- Удаление используемого атрибута — 422 с числом использований (как сейчас,
  плюс варианты).

## Тесты

PHPUnit, feature:

- Миграция: старая строка → `{ru: …}`; `down()` возвращает строку.
- Slug: генерация из ru для атрибута, бренда, категории; коллизия → `-2`;
  явный slug проверяется как раньше.
- Товар: сохранение с `attributes` — создание, изменение, удаление
  отсутствующих, без ключа — не трогает, откат транзакции при ошибке; новый
  товар с характеристиками одним запросом; ошибки валидации по индексам.
- Вариант: `attributes`, `media_ids` с порядком, 422 для фото чужого товара,
  каскад при удалении фото и атрибута.
- Атрибуты: `values_count`, `variant_values_count`, отказ удаления при
  значениях вариантов.
- Публичный API: `characteristics` на ru и kk, откат kk → ru; фасеты
  `{value, label}`; фильтр по ru-ключу при `locale=kk`; `images` и
  `characteristics` варианта, старый JSON как запасной.
- `UserController`: сортировка по `company_name`, без `sort` — прежний
  порядок.

Front-end: `npx tsc --noEmit && npm run build` в `admin/`, `storefront/`,
`b2b-portal/`; ручная проверка в браузере на ширине телефона (форма нового
товара с характеристиками и «+ Создать», вариант с фото, экран атрибутов,
выбор клиента).
