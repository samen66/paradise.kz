# Страница заказа в B2B-портале: фото, ссылки на товар, подробности заказа

## Контекст

Страница `b2b-portal/src/app/(portal)/orders/[id]/page.tsx` показывает номер, дату,
способ получения, статус, список позиций строкой «название × количество» и итог.
Партнёру не видно, какой именно товар он заказал (нет фото и артикула), по позиции
нельзя перейти в карточку товара, не видны адрес доставки целиком, комментарий,
email, разбивка суммы и статус оплаты.

API `GET /api/orders/{order}` (`App\Http\Controllers\Api\OrderController::show`,
группа `auth:sanctum` + `approved` + `b2b`) отдаёт `OrderResource` с позициями
`OrderItemResource`: `id, product_id, external_product_id, name, quantity, price`.
`OrderResource` использует и кабинет витрины (`Api\Account\OrderController`).

## Цели

1. Каждая позиция показывает фото, название, артикул, цену за единицу, количество
   и сумму строки.
2. Клик по позиции открывает карточку товара `/product/{product_id}`.
3. Заказ показывает: дату и время, статус заказа, статус оплаты, способ получения
   (склад самовывоза или полный адрес доставки), комментарий, контактный email,
   сумму разбивкой (товары / доставка / итого).

## Не цели

- Способ оплаты не показываем. B2B-оформление (`OrderPlacementService::place()`)
  его не принимает, в колонке лежит дефолт миграции `cash` — это не выбор клиента.
- Переоформление, отмена, повтор заказа — не в этой задаче.
- Кабинет витрины не меняем (новые поля в ответе ему безвредны).

## Решения

### API — только добавление полей

**`OrderItemResource`** — два новых ключа, оба из живого товара и только когда связь
`product` загружена (`whenLoaded`), иначе ключа нет:

| Ключ | Значение |
|---|---|
| `image` | URL конверсии `thumb` первого медиа коллекции `Product::IMAGE_COLLECTION`, либо `null` |
| `article` | `products.article`, либо `null` |

Если `product_id` у позиции `null` (товар удалён — FK `nullOnDelete`), оба ключа
`null`.

Название, количество и цена по-прежнему из снимка позиции: это финансовые данные
заказа. Живой товар даёт только презентацию (фото, артикул).

**`OrderResource`** — новый ключ `payment_status` (`unpaid` | `paid` | `cancelled` |
`failed`, как в колонке).

**`OrderController::show`** — загрузка `items.product.media` одним eager-load, чтобы
число запросов не росло с числом позиций. `index` не меняется: списку фото не нужны,
и ключей `image`/`article` в нём не будет.

Видимость товара клиенту при выдаче фото не проверяем: клиент уже купил этот товар,
его фото и артикул — часть его заказа.

### Портал — страница заказа

Разметка (десктоп — две колонки, на узком экране боковой блок уходит под товары):

- **Шапка:** ссылка «Все заказы», заголовок «Заказ {number}», под ним дата и время
  (`ru-KZ`), справа плашки статуса заказа и статуса оплаты.
- **Товары (левая колонка):** строка-ссылка на `/product/{product_id}`:
  фото 64×64 (`next/image`, `object-cover`; заглушка-иконка, если `image` пуст),
  название, «Арт. {article}» если есть, «{price} × {quantity}», справа сумма строки.
  Если `product_id === null` — та же строка без ссылки.
- **Боковой блок (правая колонка):**
  - «Получение»: самовывоз — «Самовывоз» + название склада; доставка — «Доставка» +
    город, улица, дом, кв., комментарий к доставке (пустые части пропускаются).
  - «Оплата»: статус оплаты.
  - «Комментарий» и «Email» — только если заполнены.
  - «Сумма»: «Товары, N поз.» = сумма `price × quantity` по строкам; «Доставка» —
    если `delivery_cost > 0`; «Итого» = `order.total` из API.
- Состояние ошибки загрузки («Заказ не найден…») и спиннер — как сейчас.

Все подписи — через `next-intl` (`ru.json`, `kk.json`), включая текущие
захардкоженные «Все заказы» и «Товары». Статусы оплаты — ключи `account.paymentStatus.*`.

Типы `b2b-portal/src/lib/types.ts`: `OrderItem` += `article?: string | null`
(`image` уже есть), `Order` += `payment_status?: string`.

### Товар, которого больше не видно

Если товар скрыли из каталога клиента, карточка по ссылке покажет штатное «Товар не
найден». Отдельный признак доступности в API не вводим: он зависел бы от контекста
вызывающего кабинета (B2B/витрина) и усложнил бы общий ресурс.

## Проверка

**PHPUnit (`tests/Feature/Orders/OrderApiTest.php`):**
- `show` отдаёт `items.*.image` (URL thumb) и `items.*.article` для товара с фото;
- позиция без `product_id` — `image` и `article` равны `null`;
- `show` отдаёт `payment_status`;
- число SQL-запросов `show` одинаково для заказа из 1 и из 3 позиций с фото;
- `index` не содержит `image`/`article` у позиций;
- существующий тест «чужой заказ → 404» остаётся зелёным.

**Портал:** `npx tsc --noEmit` и `npm run build` в `b2b-portal/`; разовый
Playwright-прогон с подменённым API: фото, артикул, ссылка ведёт на
`/product/{id}`, позиция без `product_id` не ссылка, блоки получения (оба способа),
оплаты, комментария и суммы.
